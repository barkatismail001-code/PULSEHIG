Internet Slow but Speed Test Is Fine? Here Is Why

👤 TechPulse Team 📅 2026-10-03 ⏱ 6 min read
🎯 Difficulty: Intermediate ⏱ Fix time: 20 min 💰 Cost: Free

Speed tests measure a single large download. Browsing uses hundreds of small connections, DNS lookups and TLS handshakes. That is why you can have "500 Mbps" and still wait 3 seconds for every page.

1. Test DNS latency, not bandwidth

nslookup google.com 8.8.8.8
nslookup google.com 1.1.1.1
# Linux/macOS
dig google.com @1.1.1.1 | grep "Query time"

If your ISP's DNS answers in 80 ms and Cloudflare in 8 ms, switch to 1.1.1.1 or 9.9.9.9. This alone makes browsing feel instant.

2. Check bufferbloat

Run the Waveform Bufferbloat Test. If your latency jumps from 10 ms to 300 ms under load, you have bufferbloat. Fixes:

  • Enable SQM (Smart Queue Management) on your router.
  • Set fq_codel on OpenWrt.
  • Cap download/upload to 90% of your line rate.

3. Check MTU

ping -f -l 1472 8.8.8.8
# if "Packet needs to be fragmented", lower the value until it passes
# then set MTU = value + 28

Wrong MTU causes retransmissions that look like a slow connection.

4. Disable IPv6 temporarily

Some ISPs have broken IPv6 that adds a 2–3 second fallback per connection. Test by disabling IPv6 in the adapter settings. If browsing becomes fast, call your ISP.

5. Check Wi-Fi interference

sudo iw dev wlan0 scan | grep -E "SSID|freq|signal"

2.4 GHz is crowded. Move to 5 GHz or 6 GHz, or change to channel 1/6/11.

6. QoS / traffic shaping

If one device is uploading (backup, cloud sync), everyone else suffers. Enable QoS on the router and prioritise your work PC.

7. Try a different browser profile

An extension like a "VPN" or "ad blocker" can add 500 ms per request. Test in a clean Chrome profile.

Summary

Measure DNS latency, bufferbloat and MTU — not just bandwidth. Fixing DNS and enabling SQM on the router makes the internet feel fast even when the speed test was never the problem.
